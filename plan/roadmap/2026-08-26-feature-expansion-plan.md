# 云舒卷 2.0 · 功能扩展企划书（六方向）

> 创建日期：2026-08-26
> 状态：待审核
> 目标：解决"功能单调感"——让数据有故事、使用有目标、操作有高级感，并把六个方向串成一个闭环。

---

## 1. 总览

| # | 方向 | 解决什么 | 预估 | 优先级 |
| --- | --- | --- | --- | --- |
| ① | 知识仪表盘 | 数据没有"故事" | 1~2 天 | ⭐⭐⭐ |
| ② | 连续打卡 + 每日任务 | 使用没有目标/黏性 | 1~2 天 | ⭐⭐⭐ |
| ③ | 命令面板 ⌘K | 操作效率/高级感 | 0.5~1 天 | ⭐⭐⭐ |
| ④ | 知识卡片分享 | 展示/传播 | 1 天 | ⭐⭐ |
| ⑤ | 双链 + 知识图谱 | 知识关联可视化 | 2~3 天 | ⭐⭐ |
| ⑥ | 网页剪藏 | RAG 数据源扩充 | 1~2 天 | ⭐⭐ |

**核心设计原则**：六方向不是孤立的，而是通过"**数据 → 展示 → 激励 → 联动**"串成一个闭环：

```
写笔记/回顾/对话（已有行为）
   │
   ▼
② 打卡/任务系统（目标感）──▶ 页宠好感加成（激励）
   │
   ▼
① 仪表盘（数据故事）     ⑤ 图谱（关联网络）     ④ 卡片分享（展示）
   │
   ▼
③ 命令面板（一切入口）   ⑥ 剪藏（更多数据进来）
```

---

## 2. 方向①：知识仪表盘

### 功能
- **笔记热力图**：GitHub 风格贡献图（一年 365 格，按天写入笔记数着色），悬停显示日期详情
- **字数趋势**：近 30 天写作字数折线/柱状
- **分类占比**：工作/学习/生活/技术 环形图
- **回顾统计**：本周回顾完成率、累计打卡次数
- **AI 使用**：对话次数、知识库文档数
- **页宠**：展示好感度/等级（联动）

### 技术方案
- 后端新增 `GET /stats/dashboard`：聚合 MySQL（笔记 created_at/字数/分类）+ Redis 缓存 5 分钟
- 前端图表：**轻量自绘 SVG**（热力图、环形图都很容易自绘，不引 Recharts 大依赖）或引入 `recharts`（~50KB）
- 页面：侧边栏新增「统计」入口，或作为首页/笔记列表上方卡片

### 工作量：1~2 天

---

## 3. 方向②：连续打卡 + 每日任务

### 功能
- **Streak 火焰**：连续写笔记天数、连续回顾天数（🔥 + 数字），破纪录庆祝
- **每日任务**（每日 3 个，00:00 重置）：
  - 写 1 篇笔记（或保存 1 次）
  - 完成 1 次回顾
  - 与 AI 对话 1 次
- **任务奖励**：每完成一个任务 → 页宠好感 +2（**与现有好感系统联动**，但受全局冷却约束）
- **结算页面**：当天全部完成 → 弹窗庆祝（烟花动画 + 页宠 celebrate）

### 技术方案
- 纯前端 localStorage（`pet.config` 扩展为 `habit.config` 或独立 key）：
  - `streak: { notes: {date, count}, reviews: {...} }`
  - `tasks: { date, done: string[] }`
- 事件复用现有 `usePetStore.trigger` 链路：`note_saved`/`review_done`/`ai_done` 已存在，只需加"任务完成判定"
- 侧边栏新增「今日任务」小面板或独立页面

### 与页宠联动（关键）
- 任务完成 → `addAffection(2, ...)`（受冷却控制，防刷）
- 全勤 7 天 → 特殊成就徽章

### 工作量：1~2 天

---

## 4. 方向③：命令面板 ⌘K

### 功能
- `Ctrl/⌘ + K` 全局唤起（Linear/Raycast 风格，居中模态框）
- **快速搜索**：笔记标题/内容（调用现有语义搜索接口）、知识库文档
- **快捷操作**：新建笔记、跳转页面（AI 对话/回顾/统计/养成）、切换主题、开关页宠
- 键盘导航：↑↓ 选择、Enter 执行、Esc 关闭
- 支持中文拼音首字母？（可选，先用包含匹配）

### 技术方案
- 纯前端组件 `CommandPalette.tsx` + framer-motion 动画（已装）
- 全局键盘监听（main.tsx 或 App.tsx 挂载）
- 搜索防抖 300ms 调 `notesApi.search`

### 工作量：0.5~1 天

---

## 5. 方向④：知识卡片分享

### 功能
- 笔记详情/列表 → 「生成卡片」按钮
- Canvas 渲染**精美卡片图**：笔记标题 + 内容摘要 + 标签 + 日期 + 品牌水印 + 页宠小图
- 长按/右键保存图片（PNG 下载）
- 多种模板（简约白/渐变/暗色）

### 技术方案
- Canvas 2D 绘制（`html2canvas` 太重，直接 Canvas 画文字/圆角卡片更可控）
- 中文排版：`ctx.measureText` 换行 + 省略号
- 页宠小图：把 SVG 序列化为图片（`XMLSerializer` + Image）嵌入卡片

### 工作量：1 天

---

## 6. 方向⑤：双链 + 知识图谱

### 功能
- **双链语法**：笔记中输入 `[[笔记标题]]` 自动建链（编辑器内解析 + 保存时提取）
- **关联面板**：笔记详情显示"反向链接"（谁引用了这篇）
- **知识图谱页**：节点 = 笔记/文档，边 = 双链/语义相似（复用现有 `get_related_notes`），力导向图（自绘 SVG 或 `d3-force` 单模块）

### 技术方案
- 后端：笔记保存时正则提取 `[[...]]` → 存 `note_links` 表（新模型 + 迁移）；查询反向链接接口
- 前端：Tiptap 编辑器输入时高亮 `[[...]]`（已有 Markdown 解析，正则高亮即可）；图谱页用 **d3-force 单模块**（~20KB）或自绘简单力导向
- 图谱数据源：双链 + 现有语义关联

### 工作量：2~3 天（最重，拆两步：先双链+反向链接，再图谱可视化）

---

## 7. 方向⑥：网页剪藏

### 功能
- 知识库页 → 「剪藏网页」：粘贴 URL → 后端抓取 → 提取正文（标题/段落/图片）→ 自动入库为知识库文档（走现有切片管线）
- 支持：普通网页、知乎/公众号文章（正文提取）
- 结果反馈：成功 → 出现在知识库列表（页宠庆祝）

### 技术方案
- 后端新增 `POST /knowledge/clip`：`requests` 抓取 + **trafilatura**（正文提取库，轻量）或 `BeautifulSoup` 启发式
- 抓到的正文走现有 `DocumentProcessor` 管线（复用切片/向量化/去重）
- 校验 URL 合法性 + 大小限制（防 SSRF：仅 http/https + 超时）

### 工作量：1~2 天

## 8. 联动设计汇总

| 联动 | 说明 |
| --- | --- |
| 任务完成 → 页宠 | 好感 +2（受全局冷却约束），全勤 7 天解锁成就 |
| 仪表盘 ↔ 打卡 | 热力图直接展示打卡数据，一页看全部 |
| 命令面板 ↔ 一切 | 搜索笔记/文档、跳转页面、快捷操作、开关页宠 |
| 图谱 ↔ 双链 | 双链是图谱的边；语义相似作补充边 |
| 剪藏 ↔ 知识库 | 剪藏直接入库，扩充 RAG 数据源（AI 问答更强） |
| 卡片分享 ↔ 页宠 | 卡片上带页宠小图，品牌传播 |

## 9. 分期路线图

| 里程碑 | 内容 | 预估 | 收益 |
| --- | --- | --- | --- |
| **M1** | ③ 命令面板 + ② 打卡/任务系统 | 1.5~2.5 天 | 最快见效：高级感 + 黏性 |
| **M2** | ① 仪表盘（统计 API + 热力图/图表） | 1~2 天 | 数据故事，页面丰富度大提升 |
| **M3** | ④ 卡片分享 + ⑥ 网页剪藏 | 2~3 天 | 展示传播 + 数据源扩充 |
| **M4** | ⑤ 双链（先）→ 图谱（后） | 2~3 天 | 知识网络可视化 |

**总预估：6.5~10.5 天**（分里程碑交付，每期可独立验收回滚）

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 图表库依赖过重 | 热力图/环形图自绘 SVG（<5KB），不引大库 |
| 打卡数据可伪造（localStorage） | 本地单机应用可接受；后续可上后端存储 |
| 剪藏 SSRF 风险 | 仅 http/https + 域名校验 + 超时 + 大小限制 |
| 图谱性能（笔记多时） | 只画 Top 50 节点 + 按需展开 |
| 双链破坏现有编辑体验 | 双链仅高亮展示，不拦截输入；语法错误自动忽略 |
| 任务奖励被刷 | 沿用全局好感冷却 + 每日任务本身就是上限 |

---

## 11. 建议

**按 M1 → M2 → M3 → M4 顺序实施**，每个里程碑结束都可在本机验证。M1（命令面板 + 打卡任务）最先落地，能立刻缓解"单调感"；M2 仪表盘让数据说话；M3/M4 深化知识场景。
