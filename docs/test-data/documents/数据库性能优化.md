# 数据库性能优化笔记

## 一、索引优化

### 为什么需要索引

没有索引时，数据库需要全表扫描才能找到数据。数据量达到百万级别后，全表扫描会非常慢。索引相当于书的目录，能大幅加速查询。

### 索引使用原则

1. 高频查询的过滤条件字段建索引
2. 复合索引遵循"最左前缀"原则
3. 不要过度建索引（写入会变慢）
4. 避免在索引列上做函数运算

```sql
-- 示例：联合索引
CREATE INDEX idx_user_updated ON notes(user_id, updated_at);
```

## 二、查询优化

### 常见慢查询原因

- SELECT * 取多余字段
- 深分页（OFFSET 过大）
- 缺少合适的索引
- 隐式类型转换

### 优化手段

- 只查需要的列
- 使用覆盖索引
- 分页改为游标方式（记录上一页最后一条的 ID）
- 用 EXPLAIN 分析执行计划

## 三、缓存策略

### 缓存什么

- 热点数据：排行榜、广场列表
- 读多写少：用户资料
- 计算结果：统计聚合

### 缓存注意事项

1. 设置过期时间，防止脏数据
2. 写操作后主动失效缓存
3. 缓存不可用时降级直查数据库（保证可用性）

## 四、连接池

- 连接池大小 = 核数 × 2 + 磁盘数，经验公式
- 定期回收过期连接（避免 wait_timeout 断连）
- 取连接前探活（pre_ping）

## 五、监控

- 开启慢查询日志，定位真正的慢 SQL
- 观察连接数，防止连接耗尽
- 定期检查表大小与碎片

## 小结

数据库优化没有银弹：先定位瓶颈（慢查询日志），再对症下药（索引/缓存/架构）。90% 的性能问题都能通过索引和缓存解决。
