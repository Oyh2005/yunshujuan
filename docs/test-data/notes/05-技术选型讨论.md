# 技术选型讨论

## 背景

[[产品需求文档]] 确定了"智能笔记助手"的产品方向，本笔记讨论技术实现方案。

## 前端选型

| 方案 | 优势 | 劣势 |
| --- | --- | --- |
| React + Vite | 生态丰富、构建快 | 学习曲线 |
| Vue + Vite | 上手快、中文文档好 | 生态略逊 |
| 原生 JS | 无依赖 | 维护成本高 |

结论：采用 React 18+，组件库用 Radix UI，状态管理用 Zustand。

## 后端选型

- **框架**：FastAPI（异步、自动文档）
- **数据库**：MySQL（关系数据）+ Redis（缓存）
- **AI 能力**：接入 OpenAI 兼容接口，参考 [[大语言模型基础]]

## 检索方案

检索是核心，方案见 [[RAG 技术入门]] 和 [[向量数据库]]：
- 向量检索：ChromaDB
- 关键词检索：BM25
- 混合检索 + 重排序

## 决策记录

1. 采用双链笔记格式 `[[标题]]`，与 [[产品需求文档]] 的 M4 里程碑对应
2. 默认私有，公开需显式操作
3. AI 调用全部走服务端，前端不接触密钥
